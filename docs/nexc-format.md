# NEXC / NUD v1 — 実装仕様

## 範囲

NEXC-Coreは共通符号化と復元、Maxは読み取り専用辞書の構築、Liteはディスク検索とローカル追記を担当します。Rust標準ライブラリと本プロジェクト内のcrateのみを使用し、既存圧縮ライブラリを内部エンジンに流用していません。

v1は既知の基本技法である接頭部分共有・品詞文字列の共有・可変長整数を組み合わせた独自形式と自前実装です。新しい圧縮原理や既存方式への優位性を証明するものではありません。語幹・接辞の学習、Knowledge-Aware Compressionの本格最適化は今後の研究です。

## 正規化と可逆性

入力は既存のEntry（読み、表記、品詞、u32頻度）です。Maxは読みでソートし、同じ「読み・表記・品詞」の重複は最大頻度へ整理します。この正規化済みEntry集合の4フィールドは完全に復元できます。TSVのコメント・行順・改行形式・重複した低頻度行をバイト単位で復元する形式ではありません。

Unicode文字列をそのまま保持します。読みの言語ID・関連語・語幹情報はまだ形式に含めていません。日本語以外の文字列の完全一致検索は可能ですが、言語ごとのIME解析・検索最適化は未実装です。

## ファイル配置

```text
64-byte header
compressed block 0
compressed block 1
...
block index
```

固定長の整数はlittle endianです。ヘッダーの後にブロックを連続配置し、索引はファイル末尾に置きます。ギャップ・重なり・末尾の余分なデータは拒否します。

| offset | bytes | 内容 |
| ---: | ---: | --- |
| 0 | 8 | magic: `4e 55 44 01 4e 45 58 43` |
| 8 | 4 | format version = 1 |
| 12 | 4 | block entries limit = 128 |
| 16 | 8 | dictionary generation（u64、利用者指定） |
| 24 | 8 | canonical entry count |
| 32 | 4 | block count |
| 36 | 4 | max reading Unicode scalar count |
| 40 | 8 | index offset |
| 48 | 8 | encoded index length |
| 56 | 4 | index CRC-32 |
| 60 | 4 | header bytes 0..60のCRC-32 |

generationは辞書の世代番号です。署名・日付の意味・更新順序は保証しません。未対応のmagic/version/block sizeは拒否します。

## 可変長整数とブロック

非負整数を1バイトあたり下位7bitで表し、bit7を継続フラグにします。下位グループから格納し、最大10バイトです。u64を超える値と冗長な末尾ゼロ表現は拒否します。頻度は復元時にu32へ範囲検証します。

ブロックは最大128エントリ・256KiBです。

```text
varint entry_count
varint POS_count
POS_count × (varint byte_length, UTF-8 bytes)
entry_count × (
    varint reading_shared_prefix_bytes,
    varint reading_suffix_bytes, reading suffix,
    varint surface_shared_prefix_bytes,
    varint surface_suffix_bytes, surface suffix,
    varint POS_id,
    varint frequency
)
```

POS文字列はブロック内で重複排除し、辞書順で並べます。読み・表記は直前のエントリとの共通バイト接頭部分を保持します。ブロック先頭の参照元は空文字です。共通部分がUTF-8文字の途中で終わる場合も、バイト列を連結してから全体のUTF-8を検証するので可逆です。

読み512バイトかつ128文字、表記1024バイトかつ256文字、品詞64バイトを上限とし、空フィールド・制御文字・未定義POS ID・不正UTF-8・読み順の違反・末尾余剰を拒否します。

## 索引と検索

索引レコードは `first reading / last reading / offset / compressed length / entry count / CRC-32` です。文字列は長さ付きUTF-8、数値はvarint、CRCのみ4バイト固定です。ヘッダーのblock count件を読みます。符号化索引の上限は128MiBです。

クライアントはヘッダーと索引を読み込みます。末尾読みが検索語以上になる最初のブロックを二分探索し、先頭読みが検索語以下のブロックだけを読みます。同音異義語が複数ブロックをまたいでも検索し、ブロック間で上位K件を保持します。復元ブロックはCRC・件数・索引の端点・読み長を検証します。エラーは変換APIへ伝播し、辞書破損を「候補なし」に置き換えません。

既定のLRUキャッシュは8復元ブロックです。`open_with_cache(path, 0..32)` で調整・無効化できます。索引は全量RAMに保持しますが、全エントリは展開しません。キャッシュ容量はブロック数の上限であり、プロセスRSSの固定上限ではありません。変換の公開APIではKを32以下に制限します。直接の辞書APIで巨大なKを指定すれば返却Entryも増えます。

Mutexでファイル位置・キャッシュを保護し、複数スレッドから安全に検索できます。ファイルは開いている間、不変である必要があります。別プロセスによる既存ファイルの書き換えやキャッシュ読込後の改変を監視する機構はありません。

## Maxの構築

全エントリをメモリ上で検証・ソート・重複排除し、ブロックごとに符号化します。同じ正規化済み入力とgenerationから同一バイト列を生成します。CLIの `dict build` は既存のTSVローダーを使用します。

出力と同じディレクトリに一時ファイルを新規作成し、ヘッダー・全ブロック・索引を書き込んで `sync_all` します。最後にhard linkで出力名を新規公開し、一時リンクを除去します。既存ファイルは置き換えません。hard link対応のファイルシステムが必要です。通常のエラーでは一時ファイルを削除しますが、プロセス強制終了では `.building-*` が残る可能性があります。

この公開処理は署名付きアップデーター・現行辞書ポインター切替・ロールバックではありません。親ディレクトリの永続化を含む全OSでの電源断保証は未検証です。巨大辞書の外部ソート・ストリーミング入力は未実装です。

## Lite追記ジャーナル

`.nxl` は8バイトのmagic `4e 58 4c 31 00 00 00 00` と、次のレコード列です。

```text
u32 payload_length
u32 payload_CRC32
payload = NEXC block containing exactly one Entry
```

最大payloadは2048バイトです。1語の登録は入力検証、Baseとのキー重複確認、圧縮、追記、`sync_data` の順に処理し、同期成功後にRAM上のoverlayへ反映します。書き込み失敗時は元の長さへ切り戻します。Baseのバイト列は変更しません。直近の同一キー登録が頻度を含めて以前の値を上書きします。

再起動時にレコードを順次検証します。最後のヘッダー・payloadが不足している場合のみ、その未完レコードを切り捨てます。完全なレコードのCRC不一致、不正長、復元エラーはエラーとして保持し、登録済みのデータを黙って削除しません。途中で壊れた長さが偶然未完の最終レコードに見える場合は区別できません。

同じジャーナルへの同時書き込みを防ぐため `.lock` を `create_new` で確保します。通常終了で除去します。クラッシュ後のstale lockは、使用中のプロセスがないと確認してから利用者が削除する必要があります。自動的に他プロセスのlockを奪いません。

overlayはBTreeMapでRAMに保持します。Base更新で中央に同じ語が追加されても、検索結果と論理件数は重複を除き、ローカルの頻度指定を維持します。ジャーナル自体の圧縮し直し・物理的な重複除去・削除レコードはまだありません。

## 保護と今後の課題

CRC-32は偶発的な破損の検出で、改ざん防止・署名ではありません。SHA-256 / Ed25519 / Manifest / 暗号化 / OSの資格情報管理は今後の実装です。追記は端末内の明示登録のみで、通常変換入力の保存や通信は行いません。暗号化されていないため、保護済みPersonal Dictionaryとして扱う段階ではありません。

1億語、容量1GiB/512MiB、実語彙、低電力・熱・電力、iPhone SE実機は未検証です。次は実データのライセンス確認、圧縮器との同条件比較、索引の圧縮、語幹・接辞・頻度符号化の研究、巨大辞書の外部構築、暗号化したローカル辞書、署名更新を進めます。
